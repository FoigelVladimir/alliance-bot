## С чего продолжить

Локальный контур §16.24–16.25 готов: подготовка по UUID, проверка доступа к исходному сообщению, выдача и диапазоны аудио, неизменный срок 168 часов, ссылки и защиты чтения CAS, очистка и восстановление. Главные файлы — `apps/backend/support/attachments.py`, `apps/backend/support/attachment_source.py` и `apps/backend/storage/cas.py`. Миграции: `storage/0001_initial`, `support/0008_attachment_cache`. Команды для очистки и восстановления описаны в README. Получение из ВК отключено по умолчанию; оригиналы без сохранённого URL и обновление истёкшей ссылки требуют проверенного способа чтения. На стенде ещё проверить хосты CDN, форматы, истёкшие ссылки, права токена, диапазоны на телефоне и предел передачи в веб-сервере.

Локальный контур §19.1 дополнен задачей чтения, отчётом о покрытии, общей квотой со сверкой и подтверждением границы. Миграция `vk_channel/0002_gap_history`. Чтение выключено по умолчанию. Команды `run_vk_gap_history`, `mark_restored_vk_gaps` и `resume_vk_gap` описаны в README. На тестовом сообществе предстоит подтвердить права, идентичность сообщений, границы страниц и покрытие. До подтверждения истории разрывы остаются на ручном разборе.

§19.3 подключён для человеческих карточек. `message_event` дедуплицируется, действие и подтверждение сохраняются отдельно от переписки, закрытие отменяет неначатые отправки, продолжение ссылается на исходную карточку. При пилотном переключателе ответ менеджера выдаёт «Вопрос решён». Остаются выдача других кнопок из соответствующих сценариев, автоматические вопросы и пилот формата/срока подтверждений. Миграции `support/0009_student_actions` и `vk_channel/0003_student_actions`.

Добавлены индивидуальные блокировки восстановления по §15.10 и цели сверки по §16.20. Команда `recover_support_delivery --recovery-run-id UUID` сначала сохраняет запуск в журнале БД, затем под общим карантином атомарно переводит незавершённые отправки в неизвестность, завершает восстановленные проверки и блокирует восстановленные `failed`. Повтор завершённого UUID ничего не меняет; новое восстановление заменяет прежнюю блокировку. Миграция `support/0010_response_recovery` сохраняет старые запреты и дополняет точные связи заданий.

Подтверждение из подставной истории снимает блокировку без новой попытки, сохраняя прежние отказы и черновик. Доказанная неотправка поддержана только для отсутствия допуска всех попыток в актуальной, не затронутой восстановлением БД. Пустая история и `started_at=NULL` после восстановления не разблокируют ответ. Источник доказательства отрицательного исхода за весь восстановленный интервал пока отсутствует; до его проверки запрет сохраняется. `run_support_sender --reconcile-only` допускает локальную проверку без токена и включения сетевого чтения. Полное восстановление предметной копии остаётся отдельной приёмкой §9.4.2.

Следующий локальный блок 1В — главная и внутренние уведомления по §27.4. Внешние проверки §19.4 и доказательства исходов ВК вести отдельно на новом тестовом сообществе. Этап 1Г начинается по очередности §29.1.

## Как запускать и проверять

Команды запуска и переменные среды описаны в [README серверной части](../apps/backend/README.md) и [шаблоне среды](../.env.example). Используй отдельную PostgreSQL для разработки и тестов. Для поиска на кириллице нужна сортировка `und-x-icu`. Из корня репозитория, с настроенной средой:

```sh
bash apps/backend/scripts/build_static.sh
python apps/backend/manage.py migrate
APP_ENV=production python apps/backend/manage.py collectstatic --noinput
python apps/backend/manage.py test apps/backend
python apps/backend/manage.py makemigrations --check --dry-run
node --test apps/backend/support/tests/polling.test.mjs
```

Старый тестовый туннель и сервер остановлены. Пользователь удалил старое веб-приложение VK ID, его параметры очищены из конфигурации стенда. Следующий внешний прогон будет с другим тестовым сообществом. Держи сетевые режимы ВК выключенными до настройки этого стенда. Разработка и проверки с подставными ответами могут идти локально.

На текущем ПК подготовлены отдельные контейнеры `alliance-spec-test-pg` и `alliance-spec-test-python`, после проверок они остановлены. Локальная `.env.testing` исключена из Git. Для повторного прогона запустите оба контейнера, затем `docker exec alliance-spec-test-python python apps/backend/manage.py test apps/backend --noinput`. Не запускайте параллельно второй набор Django на той же тестовой БД. Сборка на Linux проверялась в временной копии файлов с LF: текущий Windows checkout использует CRLF.

Пользователь просит следовать согласованной спецификации и экономить токены. Читай нужные подразделы и ограничивай вывод логов и тестов итогами и ошибками.
