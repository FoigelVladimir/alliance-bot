# Серверная часть

Общая система на Python + Django + PostgreSQL. Выбрана модульная организация одного приложения: бот, веб-обработчики и фоновые исполнители используют общие операции и правила. Производственного кода, зависимостей и миграций здесь пока нет.

## Материалы для разработки

| Область | Источник |
| --- | --- |
| Границы модулей и организация кода | [Технический черновик](../../docs/design_draft.md), §9.3 и §9.9–9.11 |
| VK ID, роли, заявки сотрудников, восстановление | Черновик §9.12–9.13; [MVP](../../docs/MVP.md), §2 |
| Канал ВК, поддержка, очередь и ответы | [Бот](../../docs/bot/README.md); черновик §10–11 |
| Материалы, поиск и локальная модель | [AI](../../docs/ai/README.md); черновик §9.14–9.23 |
| Регистрация, мероприятия, турниры, составы | MVP §3.2–3.4 и §14; учитывать статусы предложений |
| Расписание и посещаемость | MVP §3.5 |
| Рассылки и настройки получателей | MVP §3.6 |
| Руководитель, контроль заполнения, Excel | MVP §3.7 |
| Веб-обработчики, шаблоны и формы | [Веб-интерфейс](../../docs/web/README.md); черновик §9.17 |
| Фоновые задачи и размещение | Черновик §9.18–9.21; [infra](../../infra/README.md) |

Первый рабочий путь: доступ сотрудника → публикация материала → вопрос ВК → ответ по материалу либо передача человеку → ответ сотрудника в тот же диалог. Создание черновика материала из обращения также включено в MVP: черновик §12.4.

Точные каталоги исходников, файлы Django-приложений, ограничения базы и команды запуска появятся в плане реализации. Пустые `bot`, `web`, `models` здесь заранее не создаются. Бизнес-правила не дублируются между ВК и веб-интерфейсом; полные требования остаются в документации.
