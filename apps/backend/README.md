# Серверная часть

Общая система на Python + Django + PostgreSQL. Выбрана модульная организация одного приложения: бот, веб-обработчики и фоновые исполнители используют общие операции и правила. Базовые зависимости этапа 1А зафиксированы в [requirements.txt](requirements.txt). Серверный проект и миграции описаны в плане §29.

## Базовые зависимости

Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r apps/backend/requirements.txt
.venv/bin/python -m pip check
```

Установка и загрузка адаптера PostgreSQL проверены на Python 3.14.5 в macOS.

## Локальный запуск этапа 1А

Нужна локальная база PostgreSQL и отдельная роль для разработки. Для команды тестов роль должна уметь создавать тестовую базу. Из корня репозитория создайте `.env` на основе `.env.example`, заполните `DJANGO_SECRET_KEY` и `DATABASE_URL`. Ключ можно сгенерировать командой `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`.

```sh
. .venv/bin/activate
set -a
. ./.env
set +a
bash apps/backend/scripts/build_static.sh
python apps/backend/manage.py migrate
python apps/backend/manage.py runserver
```

Стартовая страница открывается по адресу `http://127.0.0.1:8000/`. Для проверки сборки без отладки выполните `APP_ENV=production python apps/backend/manage.py collectstatic --noinput`. Веб-сервер рабочей среды раздаёт только каталог собранной статики `data/staticfiles`.

Очередь запускается командой `python apps/backend/manage.py run_worker`. Она выполняет зарегистрированные внутренние обработчики. Список `BACKGROUND_TASK_HANDLERS` на этапе 1А пуст. Команда с `--once` выполняет доступные задачи и завершается. Обработчик готовит результат вне транзакции и возвращает функцию для записи в БД. Воркер сохраняет результат и завершает задачу в одной транзакции. Внешние отправки подключаются отдельным контрактом на этапе 1В.

Закрытые объекты хранятся в `data/cas` либо в каталоге из `CAS_ROOT`. Сервис выдачи проверяет переданное решение о доступе до открытия файла. Маршрут выдачи подключается вместе со связью объекта с прикладной записью.

Тесты на PostgreSQL:

```sh
python apps/backend/manage.py test apps/backend
python apps/backend/manage.py makemigrations --check --dry-run
```

### Серверные копии вложений поддержки

После миграций команда `python apps/backend/manage.py run_support_attachments --cleanup-only`
снимает просроченные ссылки и очищает невостребованные объекты. Для разового прохода
добавьте `--once`. Срок доступности копии составляет 168 часов с момента подготовки,
физическая очистка CAS учитывает ссылки, выдачи и возраст файлов. Каталог `CAS_ROOT`
должен быть закрыт от прямой раздачи и находиться на устойчивой локальной файловой системе.

Получение из ВК включайте на тестовом стенде через `VK_ATTACHMENT_FETCH_ENABLED=1` и
`VK_ATTACHMENT_HOSTS` со списком точных проверенных имён CDN через запятую. Затем
запустите `python apps/backend/manage.py run_support_attachments`. Загрузчик не
переходит по перенаправлениям и не обновляет истёкшие ссылки. Пока канал выключен,
сетевые проверки выполняются с подставным источником.

Перед открытием восстановленного кабинета, после остановки прежних процессов и выбора
изолированной пары БД и CAS, выполните `run_support_attachments --recover-restored`.
Команда отменяет незаконченные подготовки, снимает старые защиты чтения и закрывает
просроченные копии. На стенде проверьте лимит времени передачи в веб-сервере и чтение
аудио диапазонами. Код Django ограничивает чтение из CAS пятью минутами.

### Восполнение истории после разрыва Long Poll

Пока `VK_GAP_HISTORY_VERIFIED=0`, новые разрывы сразу требуют ручного разбора.
После проверки методов на тестовом сообществе включите этот параметр и запустите
`python apps/backend/manage.py run_vk_gap_history` с настроенными `VK_GROUP_ID`
и токеном. Воркер ограничивает число диалогов и страниц. Общая квота со сверкой
ответов составляет 12 чтений за минуту на сообщество. Отчёт в `LongPollGap.coverage`
сохраняет просмотренный диапазон и причины неполного покрытия.

После восстановления БД вызовите `mark_restored_vk_gaps` из карантина до запуска
читателя. Когда читатель подтвердит порцию нового периода и координатор разберёт
оставшиеся пропуски, оператор фиксирует согласованное решение:

```sh
python apps/backend/manage.py resume_vk_gap --gap-id GAP_ID --profile-id COORDINATOR_ID \
  --period PERIOD --position CONFIRMED_TS --notes 'Основание и оставшиеся пропуски'
```

Команда сверяет текущий период, подтверждённую позицию и права профиля координатора.
События, сохранённые во время паузы, остаются на ручном разборе.

### Кнопки студента в ВК

Сетевой режим выключен по умолчанию. На тестовом сообществе после проверки
`message_event` и формата короткого подтверждения включите `VK_CLICK_ANSWERS_VERIFIED=1`.
Приём `run_vk_long_poll` сохраняет нажатия, `run_worker` применяет их к карточкам,
а `run_vk_click_answers` отдельно отправляет короткие подтверждения. При включённом
режиме ответ менеджера содержит кнопку «Вопрос решён». У неё локальный срок семь дней.
Истечение 10-секундного срока подтверждения не отменяет действие студента.
